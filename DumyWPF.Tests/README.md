# Автотести Dumy (Етап 7)

Фреймворк: **xUnit**. Тести працюють на Windows (WPF).

## Як запустити
- Visual Studio: меню **Test → Run All Tests**.
- Термінал (Windows), у корені проєкту: `dotnet test`.

## Стратегія
| Рівень | Що перевіряємо | Файл |
|---|---|---|
| Модульні | прості правила й форматування без БД: емодзі настроїв, `RelayCommand`, рядки історії, текст «рівень втоми/інтенсивність» | `PureLogicTests.cs` |
| Інтеграційні | сервіси й SQLite: seed 18 практик, збереження настрою, звичок | `DatabaseAndServicesTests.cs` |
| Звʼязок «збереження ↔ відображення» | галочка → БД → новий екран показує те саме | `HabitsViewModelTests.cs` |
| ViewModel екранів | онбординг, навігація, «Щоденний баланс», «Фокус та Вигорання» | `ScreenViewModelTests.cs` |

## Крайові ситуації, що покриті
- порожня БД (історія, звички, нагадування «немає записів»);
- записи за вчора не рахуються як «сьогодні»;
- дуже швидкі кліки по звичці не створюють дублікатів (20 паралельних збережень → 1 рядок);
- порожні / пробільні нотатки зберігаються як `null`;
- межі шкал 1–10 (3/4, 6/7, 8/9), округлення повзунка;
- повторний `Initialize()` не дублює практики;
- невідомий стан настрою → емодзі за замовчуванням.

## Безпека даних
Кожен тест працює з власним тимчасовим файлом бази (`AppDbContext.DbPathOverride`), тому ваш справжній `dumy.db` не змінюється.

## Не автоматизовано (перевіряється вручну)
Вікна `MessageBox` (напр. «оберіть режим» в онбордингу), вигляд XAML та кольори.
